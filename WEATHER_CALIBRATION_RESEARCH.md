# NYC prior-day archived-forecast calibration (research only)

**Registered on September 26, 2026, after today's public climate-book cutoff.** This is separate from the [seven-date forward quote and climate-label study](WEATHER_FORWARD_STUDY.md). It retrieves historical data to understand whether a coarse GFS forecast is systematically biased versus the exact New York City (CLINYC/KNYC) report. It does **not** imply that a prior historical market had a quoted opportunity or that an account made any money.

The fixed historical sample is **June 1–September 25, 2026**, inclusive. GFS grid hourly 2 m temperatures are retrieved from Open-Meteo's **Single Runs API** using exactly the run initialized **12:00 UTC the day before the target date**; local target-date maximum is derived from all 23–25 America/New_York hours. The API's documentation says global model publication generally follows initialization by 4–6 hours, so the run nominally precedes the existing study's 18:00 Eastern previous-day decision time. Historical issuance cannot be independently reconstructed to the minute: this is a limitation, not a proof of actual as-of availability. Never use the Historical Weather/reanalysis API or a stitched current forecast for a backtest.

For each date, the label is exclusively the Weather Company `cliId=NYC`, `icao=KNYC` official row with the matching `reportDate`, `data.isOfficial=true`, numeric `maxTemp`, and status `official`; revised, missing, duplicate, or contradictory rows are excluded. **Before retrieving or promoting these NYC labels**, the live event's binding rule must parse to the exact identity `New York City (CLINYC)`; any other city/station aborts. These *present-day* official records may differ from the **first official** report Kalshi used at historical settlement; this project does not call them audited Kalshi outcomes. Model coordinates (40.7833, -73.9667) are the prior independently resolved KNYC station point, not a claim that GFS grid max equals the station thermometer maximum.

The training set ends **August 31**; the strictly later **September 1–25** dates are held out. The ±5 °F comparable-forecast support gate and 15-train/10-holdout minimum are **post-observation safeguards**, not preregistered hyperparameters or evidence of a working strategy; no station location is tuned using holdout labels. For each rule, calculate probability from **only** training residuals whose archived grid forecast is within ±5 °F of today's grid maximum, with Laplace smoothing and a Wilson binomial lower bound. If the comparable-day minima fail, probability and Wilson lower are **null/unsupported**, rather than an all-season substitute. Compare rule-specific Brier loss against a training-label-frequency baseline on *only* chronological holdout days each having at least 15 locally comparable training forecasts; require 20 such scored days and today's regime support or mark both Brier values unsupported. Show the current real YES ask, actual displayed size, and series-specific non-direct fee-inclusive one-contract hurdle only when a fresh book exists. Residual resampling is not guaranteed: observations are correlated and seasonal, so the Wilson bound is **not** a verified 95% coverage guarantee. Missing archived runs remain explicit; they may be excluded from exploratory error estimates, but **any gap suppresses the positive trading screen** rather than impute a favorable outcome. A missing-date count above five invalidates the evaluation entirely.

**September 26 correction:** the first private scorecard's high `P(<65 °F)` estimate used all summer training residuals in an autumn forecast regime with only **1 nearby training day / 4 nearby holdout days**. An independent review identified this unjustified extrapolation and a potential station-binding mismatch. The corrected scorecard returns **unsupported**, not a probability or Brier estimate, for the 64.9 °F target; the original scorecard is **superseded, not trading evidence**. The archive has **115 valid source observations** and two explicit gaps (June 11 and September 15); none is a historical executable quote or profit proof. Zero of 24 held-out station highs were below 65 °F, but that small, seasonally mismatched count neither proves nor disproves the next day's outcome.


**No automatic order is authorized by this study.** A preliminary screen row, if any, is merely a research hypothesis; the required evidence for a live system is forward unrevised source outcomes, contemporaneous executable quotes, actual fills/fees, a bounded risk ledger, and a defensible *out-of-sample* lower bound for realized net profit. The previous isolated single-contract pilot lost **$0.0276**, which cannot be turned into a win by recalibration.

The free [Open-Meteo API](https://open-meteo.com/en/terms) is restricted to non-commercial use; this archived sample is a one-time research analysis, **not** a third-party for-profit trading feed. Additional usage would require appropriate licensing. See [Single Runs documentation](https://open-meteo.com/en/docs/single-runs-api), [TWC's settlement portal](https://weather.com/kalshi), [Kalshi's binding temperature terms](https://assets.kalshi.com/contract_terms/GLOBALTEMPERATURE.pdf), and [the current fee schedule](https://kalshi.com/fee-schedule).

Run offline verification with `python3 -m unittest tests.test_weather_calibration tests.test_weather_calibration_report -v`. A private output directory is required: `python3 weather_calibration.py --output logs/weather_calibration/nyc_2026-09-26.json` followed by `python3 weather_calibration_report.py logs/weather_calibration/nyc_2026-09-26.json --output logs/weather_calibration/nyc_2026-09-26.md`.
